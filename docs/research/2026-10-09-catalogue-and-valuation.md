# Catalogue and valuation recovery research

Researched 9 October 2026 (Asia/Dubai). Scope: primary documentation, retailer pages, and the current implementation. This is a researched implementation proposal, not a live end-to-end pricing pass. No paid API, private-image upload, retailer login, purchase, dependency installation, or product change was performed. Search/index observations can be stale; they cannot be committed as today's claim prices without a fresh source retrieval.

## Decision

Build a small, inspectable catalogue resolver and source-specific quote adapters behind the current evidence validator. First prove known identity → discovered product URL → retrieved selected offer → accepted quote independently of vision. In parallel, repair physical inventory and readable crops. Only join them after both seams work.

For the employer showcase, prioritize honest funnel metrics, edition ambiguity, independent new/used evidence and reproducible failed cases. For a later consumer inventory product, add receipt/link-assisted review and persistent refresh as separate capabilities. The assignment still requires one continuous sweep: runtime must not require barcode scans, typed ISBNs, book removal, or individual photographs. Development annotations and catalogue fixtures are evaluation evidence, not runtime inputs.

## What exists and why it returns empty results

The [implementation review](../2026-10-09-implementation-review.md) records two independent failures: few tracks qualify for pricing, and the separate five-known-book discovery experiment found 0/5 eligible URLs. Seeded-page extraction recovered 3/5 new UAE quotes and 0/5 used quotes. These are coverage observations, not the assignment's 15-book price-accuracy result. Preserve them in [preflight results](../preflight-results.md).

In `backend/price_sources.py`, the generic path requires a single JSON-LD Book/Product with exact normalized title and author, canonical page URL, explicit print format, and a single Offer with explicit condition, stock, price/currency and market country. It considers `eligibleRegion` and seller address for market evidence, but not `shippingDetails.shippingDestination`. Amazon.ae has a separate selected-offer adapter and supports only new AED quotes. This is code evidence, not a claim that a particular failed page necessarily lacked every field.

These requirements are stricter than real retail markup. Titles often include subtitles/format suffixes, author metadata can be absent, product identity can be linked by `@id`, and availability/variant selection can be rendered separately. Schema.org distinguishes delivery eligibility from seller location and supports shipping destinations. Consequently, seller address alone is not proof of buyer delivery, and absence of that JSON-LD field does not prove a listing unavailable. Repair extraction through demonstrated source shapes; do not let the model fill missing facts. [Schema.org Offer](https://schema.org/Offer).

Discovery presently asks a model for cited URLs. That is a candidate generator. A citation proves the URL was returned, not edition match, stock, condition, price, or retrievability. Keep citation provenance; measure failures at URL generation, fetch, parsing and quote admission separately.

## Verified catalogue interfaces

**Open Library: preferred initial metadata candidate provider.** Its Search API returns work-level records and selected edition information. Default search returns works; the best-ranked edition is not proof of the copy on a shelf. Request bounded fields and title/author evidence, then inspect specific edition records only when visible clues justify it. Cache responses and identify the application. Official limits are 1 request/second by default and 3/second for identified requests; the documentation discourages hundreds of single-book lookups and high-traffic commercial backend use. Thus it suits a small human-triggered showcase, subject to its guidelines; commercial scale needs a separate data/access decision. [Search API](https://openlibrary.org/dev/docs/api/search), [API usage and rate limits](https://openlibrary.org/developers/api).

Open Library says it asserts no new proprietary rights over database material, while noting existing rights issues may remain. Do not label the entire database or covers unconditionally public-domain/CC0. Use metadata attribution and review cover/data rights before public redistribution. [Licensing](https://openlibrary.org/developers/licensing).

**Google Books: optional corroboration, with a commercial blocker.** Volume search supports title, author, publisher and ISBN terms, requires application identification through API key/OAuth, and returns identifiers/metadata. The official guide does not establish an account-independent daily quota here: inspect the configured project's quota before planning throughput. Its supplemental terms currently state that charging users for the application requires a separate agreement or written permission. Treat this as a release gate for a paid consumer product. [Using the API](https://developers.google.com/books/docs/v1/using), [Books API terms](https://developers.google.com/books/terms), [branding](https://developers.google.com/books/branding).

Google's `saleInfo` relates to its eBookstore and contains `isEbook`, country and price. It is not a source for the physical owned book's replacement/used valuation. Use Google Books as metadata support, with attribution, rather than a shortcut around retailer retrieval. [Volume resource](https://developers.google.com/books/docs/v1/reference/volumes).

**Identity policy.** Preserve observed text independently of resolved metadata. Resolve a work from readable title/author and discriminating visible clues; catalogue lookup must not rescue an unreadable spine solely because a famous title is plausible. Candidate ISBNs remain candidate ISBNs unless the owned edition is supported. ISBN identifies a particular edition/format: paperback and hardcover can have different identifiers even with the same cover. [Bowker publication formats and editions](https://www.myidentifiers.com/faq/publication). Library metadata supports identity, not existence, multiplicity or actual physical dimensions.

## Approaches and recommendation

| Approach | Strength | Failure/cost | Decision |
| --- | --- | --- | --- |
| General model search + generic JSON-LD only | Existing implementation; broad candidate discovery. | Search and markup mismatch remain opaque, edition/selected-offer details disappear, zero quotes can look like “nothing found”. | Retain as discovery/fallback; not sole pricing architecture. |
| Small source registry + bounded search + deterministic adapters | Source-specific field evidence, stable negative fixtures, independent coverage metrics; practical showcase scope. | Adapter maintenance, source access/terms and dynamic stock still require probes. | Recommended immediate path. Start one UAE new source, one UAE used source, one US source demonstrated live; expand after gates. |
| Contracted catalogue/retail APIs or licensed feeds | More stable access and structured fields for commercial operation. | Credentials, licences, approval, recurring cost, and regional coverage may block rollout. | Evaluate for consumer scale; do not make showcase recovery wait on unapproved APIs. |

Adapter interface should return candidate URLs first, then parsed source evidence, then a validated quote. It should own source-specific redirects, product/variant identifiers, condition labels and market proof. Shared Python owns identity/equivalence acceptance, currency conversion, appraisal, numeric validation and totals. Keep per-host concurrency/rate budgets, cache metadata separately from time-sensitive quotes, and stop bounded retries on denial/challenge pages. Do not bypass authentication or anti-bot controls.

For title matching, replace exact whole-string equality only through a documented equivalence check: normalized base title, supported subtitle aliases, author identity, language and binding, plus publisher/year when visible. A catalogue-assisted match must retain the supporting record. Ambiguous translations, abridgments, textbooks with materially different editions, bundles and signed/collector listings abstain. An exact edition price and an equivalent ordinary replacement are different evidence classes.

## Quote contract and gates

Every accepted quote needs: owned instance ID; identity evidence and revision; source/provider; final retrievable product URL; source product/variant/offer ID when available; retrieval timestamp; original price and ISO currency; condition; binding/language; listing ISBN/edition when available; exact/equivalent assessment and reason; stock and market/delivery evidence; price basis (asking retail, not realized resale); selected-offer evidence; conversion provenance if needed. Store permitted evidence snapshots locally with hashes and parser version; do not redistribute entire scraped pages by default.

Use these project gates before promoting adapters:

1. Re-run the fixed five known identities and report a funnel for **each locale/condition**: input → URL → fetched page → matched edition/equivalent → bound offer → accepted quote. Hand-inspect every accepted quote; disclose failed and missing cases. Seeded URLs may test extraction but cannot pass discovery.
2. Add negative fixtures for recommendations, all-edition minima, crossed-out MSRP, foreign currency, changed variant, missing author, seller/delivery mismatch, condition-switch stock, bundles and contradictory DOM/JSON-LD. Acceptance must never depend on a model-created number.
3. Expand to the same ten books in AE/AED and US/USD through one locale-parameterized interface. Keep identical instance identities and explicit equivalent substitutions. Foreign conversion is labelled fallback, never presented as local market evidence.
4. Independently check the assignment's 15 comparable book prices and ≤25% mean relative error. Predeclare sample and source types; report missing-output rate and accepted-quote coverage alongside error. No silent removal of unpriced cases and no inferred used discount.
5. Demonstrate actual post-sweep latency under five minutes with source budgets and partial-stage reporting. A fast empty packet is not this gate. A price can be shared between confirmed identical copies for efficiency, but instance multiplicity and ownership exclusions remain independent.

Rare/signed/antiquarian/collector candidates and existing high-value appraisal routing remain excluded from automatic amounts. A user edition assertion is recorded provenance, not verified monetary evidence. Price precision and confidence cannot exceed source evidence.

## Non-book ranges and FX

For known brand/model, compare like-for-like SKU/variant and market. For unknown ordinary furniture/lamps/textiles, build a **sourced comparable range** from individually retrieved replacement products with similar function, visible material/style and supported size class. Every endpoint needs an attributable listing; the range is a spread across comparable products, not a statistical confidence interval. Do not invent a SKU, use the cheapest unrelated product, or substitute retailer dimensions for measured owned-object dimensions. Unknown material/dimensions can prevent a defensible comparator; preserve null and review. Original/unknown art stays `needs_appraisal`; an established reproduction remains a recorded assertion with print-specific comparators.

The current `backend/fx.py` already uses ExchangeRate-API's no-key endpoint, validates positive rates/base and timestamps, and caches responses. Keep it: the provider documents daily updates, cache permission, personal/commercial conversion and attribution, while prohibiting data redistribution. Honor linked attribution in report/UI, retain data time plus fetch time, and do not treat reference FX as a payment/exchange quote. The current ≤48-hour data age is a project policy, not a provider guarantee. [Open access endpoint](https://www.exchangerate-api.com/docs/free).

CBUAE publishes dated AED reference rates specifically for VAT obligations. It is an authoritative cross-check for AED research, not an unrestricted pricing API or consumer transaction quote. Do not replace runtime FX with remembered USD/AED parity; retrieve and record the rate used. Source use/retention must fit its stated purpose. [CBUAE rates and purpose](https://centralbank.ae/en/forex-eibor/exchange-rates/).

## Remaining unknowns

Live source adapter coverage, retailer permission, condition-specific stock, international delivery and shipping charges remain unproven. Price accuracy for 15 books, ten-book locale parity and full-sweep pricing latency are NOT MEASURED. Catalogue recall and confidently wrong identity rates are NOT MEASURED. Consumer willingness to trust ranges and tolerate review is NOT MEASURED. Catalogue quality, edition ambiguity and sparse local used inventory cannot be solved by a stronger prompt alone. Ship visible evidence and abstention as part of the portfolio product's trust story, then measure whether the user can resolve the queue efficiently in a separate assisted mode.
