# Vision and identification recovery research — 9 October 2026

Status: research and proposed experiments, not a measured implementation decision. Sources accessed 9 October 2026. No model weights, dependencies, paid calls or private-image uploads were made for this research. Original runs remain unchanged.

## Decision

Repair the representation before changing the language model: a sweep needs coverage of distinct shelf rows, separate physical book instances, and original-resolution reading evidence. Use the existing atlas as a spatial ledger when registration passes; retain separate local views when it fails. Compare two pretrained candidates offline on independently labelled real shelves: **Grounding DINO tiny** for semantic proposals and **SAM 2.1 tiny** for masks. Neither is a proven spine counter. Keep the original SAM ViT-B as an optional replication control, rather than adding three models to the runtime.

Do not deploy an automatic physical-count result until the comparison passes the local gates below. If both fail, an explicitly assisted shelf review can make a useful portfolio milestone, but it must be described as assisted and does not satisfy the assignment's automatic-count bar.

## Evidence that constrains the choice

The [implementation review](../2026-10-09-implementation-review.md) and [preflight log](../preflight-results.md) record failed contour/boundary/VLM counting, failed same-spine matching, saved frames skipped under provider latency, and portrait capture at 480×640. Those are local field results. More prompts or a newer detector cannot recover frames that never reach inventory processing.

The directly relevant [library inventory paper](https://arxiv.org/html/2407.19812v1) uses high-resolution shelf photographs, SAM proposals, commercial OCR and catalogue matching. Its masks were manually checked; multicolour spines split, adjacent books merged, and signs/partial books survived filtering. Full detection-plus-matching accuracy was 0.641 against the library catalogue for its strongest reported method, below its matching-only result. This is evidence for separating stages and evaluating the complete funnel, not evidence of an available automatic solution. Its one-to-one catalogue matching assumption is also unsuitable for a personal collection with duplicate copies. **Inference:** allow multiple physical instances to resolve to the same work, plus an explicit unmatched outcome.

The authors' [repository](https://github.com/llabres/library-dataset) provides annotations, target lists and image download links; it is MIT-labelled. The reviewed top-level documentation does not establish a dedicated pretrained spine detector checkpoint. Treat it as a useful external evaluation resource, subject to checking download/data terms before redistribution; it does not replace local phone-sweep truth. Do not adopt a random similarly named repository: many “spine segmentation” results concern medical images.

## Runnable candidates and their limits

“Runnable” below means an official inference route exists. Installation, Python 3.12 dependency resolution, Mac memory and inference performance have **NOT BEEN MEASURED** here. Read-only checks found `arm64`, Python 3.12.11 and `cv2`; `torch`, `transformers`, `sam2` and `easyocr` are absent from the project environment. Python compatibility is a package-resolution gate, not a claim of a successful install.

| Candidate | Verified availability and licence | Proposed local route | Why test it / why it can fail |
|---|---|---|---|
| Grounding DINO tiny | Official [IDEA model card](https://huggingface.co/IDEA-Research/grounding-dino-tiny) publishes Transformers/safetensors weights and Apache-2.0 metadata. The [original repo](https://github.com/IDEA-Research/GroundingDINO) documents CPU-only inference. | Prefer the Transformers implementation, FP32 CPU first, in a separate experiment environment. Test native MPS only after output parity. | Text prompts distinguish books from lettering, labels and furniture; dense thin touching spines may still merge or vanish. It provides boxes, not validated physical identities or measurement quadrilaterals. Test “book” and “book spine” as a fixed small prompt comparison, without injecting the known count or titles. |
| SAM 2.1 tiny | Meta [publishes checkpoints](https://github.com/facebookresearch/sam2) including 38.9M-parameter tiny; model checkpoints/code are Apache-2.0. Its optional connected-component dependency has a separate licence. | Native macOS CPU/MPS route exists; start with image masks on selected row crops, not whole-video propagation. | Mask boundaries may improve crops and instance geometry. | Original SAM ViT-B, optional | The [official repository](https://github.com/facebookresearch/segment-anything) links pretrained ViT-B weights, automatic-mask and point/box prediction APIs, and Apache-2.0 model licensing; requirements specify Python ≥3.8 and PyTorch ≥1.7. | CPU baseline on a very small frozen sample if SAM2 results need a reference-paper control. | Useful for diagnosing whether pipeline differences explain the published approach. The [Transformers Grounding DINO docs](https://huggingface.co/docs/transformers/en/model_doc/grounding-dino) expose `AutoProcessor`, `AutoModelForZeroShotObjectDetection`, postprocessed image-coordinate boxes and `disable_custom_kernels`. **Inference:** disabling custom kernels is a reasonable portable probe configuration; it does not prove MPS support or speed. Use a pinned revision, processor configuration and actual sent dimensions; map outputs once to original pixels and test the mapping separately.

Meta's [installation instructions](https://github.com/facebookresearch/sam2/blob/main/INSTALL.md) recommend Python ≥3.10, torch ≥2.5.1 and matching torchvision; skipping the CUDA extension is supported but omits its small-hole/sprinkle postprocessing. The [official demo guide](https://github.com/facebookresearch/sam2/blob/main/demo/README.md) documents native MPS/CPU, warns about lower FPS and MPS memory crashes, and says Docker on macOS is CPU-only. Its demo Python example uses 3.10, so it is not verification of this project's 3.12 environment. The published SAM2 FPS numbers are A100/CUDA measurements, not a Mac latency promise.

The [Transformers installation guide](https://huggingface.co/docs/transformers/en/installation) currently targets Python 3.10+ and PyTorch 2.4+; [PyTorch package files](https://pypi.org/project/torch/) provide CPython 3.12 macOS arm64 wheels. This makes the route plausible, not installed. [PyTorch MPS docs](https://docs.pytorch.org/docs/main/notes/mps.html) provide availability checks; check them on the actual machine instead of inferring GPU availability from `arm64`.

Local inference has no provider per-image fee after weights are available, but compute, storage and setup time remain costs. Keep image paths local, disable telemetry where applicable, and run offline after setup. Record the first-run weight download separately from warm inference. Avoid hosted demos/inference widgets with private shelves. External catalogue queries disclose observed text, even when images stay local.

## Coverage and shelf atlas: practical design

The [OpenCV homography tutorial](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html) describes the planar/pure-rotation assumptions underlying a homography. A handheld sweep with protruding or differently oriented books violates a single-plane assumption. **Inference:** a row atlas can be useful after registration checks, but a room panorama must not become authoritative evidence through visual attractiveness alone.

Proposed sequence, retaining the existing implementation where possible:

1. Persist high-resolution originals before asynchronous model work. Keep a separate compact latest-view channel for voice. Each frame has a stable id, timestamp, actual negotiated dimensions, quality statistics and selected/rejected/deferred reason.
2. Build a bounded keyframe manifest independently of model latency. Select sharp views with new supported row coverage and enough overlap for registration; retain a second readable view where available. A slow call must not delete distinct shelf sections. Begin with an experimental 30–50% overlap instruction; measure registration success rather than present that range as universal.
3. Assign row/scene candidates; confirm continuity from ordered overlapping evidence. Compare local geometry and appearance inside a registered neighbourhood, not every crop in the room. Do not use an inferred title as a physical-instance id. Identical copies remain separate.
4. Reject unreliable registration using existing warp/parallax checks and measure reprojection error on labelled correspondences. Preserve disconnected row segments explicitly. A gap or unsupported view stays in the coverage ledger/review queue and cannot be archived as if counted elsewhere.
5. Detect locally on row views/tiles at useful resolution. Preserve transforms and overlap ownership. Do not add raw tile counts or merge every overlapping box; adjacent narrow books can legitimately overlap in perspective.
6. Associate instances through accepted row coordinates and temporal evidence. Use a count from validated instances; publish unresolved instance/count status separately. Repeated visits must neither add copies nor erase distinct rows.
7. Read selected original crops rather than blended atlas pixels. Stitching seams and resampling can damage lettering. Atlas coordinates organize evidence; the original frame remains the authority for reading and measurement.

There is no researched universal “minimum spine width” that establishes legibility across fonts, glare and camera motion. Establish a local resolution curve: native originals versus 720/1080/1280-pixel-long-side variants and current compact voice views. Measure title accuracy and confidently wrong readings by pixel-width/letter-height bins, holding the crop and model constant. Upscaling cannot reconstruct missing printed evidence; request a closer, slower view when the best crop remains unreadable.

## Reading and catalogue resolution

Use an independent local OCR baseline before assuming a large multimodal call is necessary for every book. [EasyOCR's official README](https://github.com/JaidedAI/EasyOCR) documents CPU inference, multilingual readers, local boxes/text/confidence and downloadable weights under an Apache-2.0 repository. Its [API docs](https://www.jaided.ai/easyocr/documentation/) support per-box rotation alternatives, contrast handling, canvas size and disabling automatic downloads. Language combinations have restrictions. Separate weight terms/provenance should be recorded for the chosen detector/recognizer assets; repository licensing alone is not a reason to skip that record.

Proposed comparison: existing VLM crop reader versus OCR on exactly the same best original crops, then a bounded VLM fallback for unreadable/conflicting OCR. Preserve literal text and orientation for both. Recognition scores are ranking signals; calibrate acceptance on independent labels. Earlier scene text may flag a conflict but should not overrule a strong crop automatically.

[Open Library Search API](https://openlibrary.org/dev/docs/api/search) offers title/author searches and work/edition fields, including edition-specific search. It can return a candidate set for noisy readings; it does not establish which edition the owner possesses. Keep work identity separate from edition/ISBN; missing edition evidence stays unknown. Use a small title/author candidate set, cache public responses, record URL/time/query and retain a none-of-these result. Do not force a candidate because it ranks first, and do not treat catalogue metadata as a price.

The current [API usage guidance](https://openlibrary.org/developers/api) asks applications to identify themselves, cache responses and avoid hundreds of individual-book requests; default limits are 1 request/second, or 3/second with identified requests. It supports human lookup and educational/open-source uses, not a high-traffic commercial backend. **Inference:** a bounded portfolio prototype can use it conservatively; scaling a commercial claim product needs a separately suitable catalogue/data agreement. Confirm current terms before deployment.

## Experiment protocol and promotion gates

These are proposed engineering gates; the PDF scoring contract remains authoritative. No gate below has been run by this research.

| Experiment | Inputs/control | Output and proposed decision |
|---|---|---|
| Environment smoke | Isolated Python 3.12 environment; official pinned versions/revisions; one consented local image | Dependency resolution, weight hashes/licences, CPU result and peak memory. FAILED/BLOCKED if unavailable; no fallback silently installs into product. |
| Detector comparison | Existing frozen row14 as regression only; additional independently labelled shelf rows held out from tuning; upright, tilted, touching, multicolour, identical copies, horizontal stacks, partial/glare/blur/non-book text | Per-scene count error plus precision/recall at IoU≥0.5; split/merge/false-positive and missing-output rates. Suggested promotion target: ≥0.95 precision and recall on readable full instances, no silent exclusion of stacks, and ≤5% physical-count error on a new sweep. A coincidentally correct count with poor matches fails. |
| Coverage/association | Saved sequence containing at least two distinct rows, revisit, partial overlap and disconnected view; physical instance labels made independently | Every selected/deferred/rejected view has a reason; no row disappears; duplicate-copy/revisit cases correct; gaps visible. Evaluate counts without supplying known totals to models. |
| OCR/VLM resolution | Fixed independently hand-read crops, multiple resolutions, multilingual/series/author-only and unreadable cases | Correct titles ≥70% of hand-legible truth, confidently wrong ≤3% per contract; report unreads and denominator. Lock thresholds on development set before held-out run. |
| Mac runtime | Warm/cold CPU; MPS only if available; full bounded row pipeline | Wall time, p50/p95, peak resident memory, selected views, output failures, crop reads and per-provider usage. Fit the complete <300-second packet budget after reserving pricing/measurement time; a fast detector alone is not a pass. |

A detector experiment should stop after the fixed comparison budget. If none passes, record the failure, show editable instance overlays for a portfolio demonstration, and plan a dedicated labelled training dataset as a separate scope. Fine-tuning is not a credible immediate fix without enough varied labels, frozen holdouts, weight provenance and a measured training/runtime budget. Do not repeatedly tune on the original 14-book row.

The strongest portfolio evidence would be a repeatable saved-sweep evaluator, a clear inventory/evidence view, the measured failure-to-improvement curve, and a demo where a missed/unclear spine requests recovery instead of becoming a confident claim. These are recommendations, not performance achieved.
