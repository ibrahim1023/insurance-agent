## Intent and constraints

Build a local-demo insurance-claim agent for a **single continuous, under-three-minute iPhone browser sweep** of one enclosed library room. The user sees inventory appear, receives active spoken guidance, can interrupt and correct it by voice, and receives an evidence-backed JSON and HTML claim packet within five minutes of ending the sweep. This is an accuracy/evidence exercise, not a polished insurance product. The final compliant room has at least 60 books, two shelving units, eight non-books, and visible wall/floor geometry; the smaller development room is not a substitute for final evaluation.

Use an iPhone browser, a visible A4 reference, OpenAI credentials, the proven plain-browser JavaScript capture/voice interface, a local FastAPI/Python server, and the filesystem. The owner approved retaining the existing browser interface rather than a React/TypeScript migration on 2026-10-07; this changes implementation preference, not the assessment's functional or accuracy requirements. No authentication, hosted database, queue, agent framework, deployment, policy database, or invented facts. Do not add native iOS code. The full build is in scope for planning, but must be delivered in independently testable stages within the 15–20-hour engineering budget in `build-spec.md`.

**Evidence rule:** models propose semantic facts; deterministic code owns evidence links, state changes, measurements, prices, validation, and arithmetic. Unknown is a valid output. Passing accuracy thresholds is a measured outcome, not a design claim.

## Capture and interaction

The browser obtains camera and microphone permissions from a user gesture on a secure origin, shows continuous camera preview and sweep status, and uploads timestamped sampled JPEG frames (initial target 1–2 FPS, adjusted after device testing). Keep useful originals/crops, never spend a model call on every camera frame. Frame identifiers are stable within a sweep. On-device or server-side cheap blur, exposure/glare, and motion signals feed guidance; sampled frames and cheap scene-change filtering limit server work. If the device or network cannot sustain capture, show a warning and preserve the partial sweep rather than silently discarding it.

OpenAI Realtime over WebRTC handles simultaneous two-way voice, interruption, and short spoken capture instructions. FastAPI establishes the session with the provider while keeping the long-lived API key server-side. The browser sends/receives audio on media tracks; inventory/state updates travel through the app API, not through unvalidated speech text. The voice model proposes typed correction intents (for example exclude shelf, ownership exclusion, edition claim, artwork print status); Python validates target, provenance, and effect before applying them to sweep state. A user's unsupported edition claim remains a recorded assertion, not automatic proof of a first edition or an automatic price. Guidance is based on capture-quality/coverage events; the voice layer cannot set totals or invent a completed measurement. Early device acceptance test: Safari camera preview, mic, WebRTC speech/interruption, frame upload, and live updates run together for one sweep.

The app shows books detected/identified/unidentified, non-book candidates, warnings, current instruction, and post-sweep processing. It must not imply a model suggestion is a confirmed claim fact. The capture remains continuous; a short targeted pause or re-aim during that sweep is allowed, not a second scanning pass or individual book photography.

## Processing boundaries and records

One FastAPI process owns sweep endpoints, in-memory active state, and lightweight in-process post-sweep tasks; per-sweep files under `runs/<id>/` hold metadata, frames, crops, stage outputs, packet, and report. State writes should be atomic to avoid half-written JSON. On restart, saved evidence and stage outputs remain inspectable; an interrupted job can be reported incomplete rather than pretending it finished. No persistence service is added until a demonstrated need.

```text
Browser camera ──> frame sampler/upload ──> quality/coverage ──> detection
      │                                                    │
      └── WebRTC voice <── validated state/events <── tracking + corrections
                                                    │
                                    best crops ──> identification
                                                    │
                          calibrated measurement + retrieved prices
                                                    │
                            deterministic validation/review/totals
                                                    │
                                 claim_packet.json ──> report.html
```

Use strict structured records (Pydantic on the server) for Sweep, Frame, CaptureIssue, Shelf, BookTrack, Identification, Measurement, NonBookTrack, PriceEvidence, RoomMeasurement, ReviewItem, and ClaimPacket. Persist stage outputs separately; the final packet is a projection of validated state, not the direct output of one model call. A reference includes the frame ID and, where applicable, crop ID and measurement/price provenance. Every packet frame reference must resolve to a saved frame.

Book existence begins with visible upright, flat and stacked spine candidates; proposed cross-frame associations are evidence, not a physical count. The per-shelf atlas gate below owns counting distinct supported spines. Never use OCR count as book count. Save a small number of best crops per persistent book, selected by clarity, glare, resolution, and visibility. Send only useful crops to the explicitly selected image-reading provider for title/author and edition **when visible**; corroborate proposed metadata when possible. Identifications below conservative evidence thresholds remain `unidentified` with empty strings for unsupported title, author, edition, and ISBN. Potentially signed, rare, antiquarian, or collector-grade books are `needs_appraisal`. Do not automatically price those even if a listing appears. A sourced candidate price exceeding AED 1,000 equivalent is conservatively routed to appraisal pending review; this is a routing threshold, not an estimate of the item's value. A user correction takes precedence as an assertion, with source preserved, but cannot make an unsupported value authoritative.

### Replacement book inventory: per-shelf visual atlases

The fixed-scene modal count and per-spine SIFT/ORB/point-flow matching are **failed baselines**, not the count architecture for a moving camera. In the owner-counted 59-book sweep, 117 saved 480×640 frames produced only eight analyzed views, 71 provisional tracks, 58 duplicate flags and no supported physical count. Those views showed different sections; frozen pair labels yielded no trustworthy per-spine identity links. Preserve all failures in `docs/preflight-results.md` and the original runs. Never fit a count to 59, sum frame detections, merge on title alone, or claim hidden books.

**Capture and keyframes.** Keep one continuous iPhone browser pass, concurrent voice, timestamped saved originals and the existing bounded-cost FastAPI/filesystem design. The browser requests a higher-resolution rear camera only after an iPhone Safari concurrency/upload preflight measures the *actual* `MediaStreamTrack.getSettings()` resolution, frame freshness, latency and failures; do not assume a requested width is delivered. Retain cheap blur/glare/overlap signals on saved frames. Select clear, overlapping keyframes **for each shelf row** from the one-FPS stream rather than always analyzing the newest frame after a slow model call. During the same pass, speak a short hold/overlap instruction if a row is missed; do not request individual photos or a second pass. Keep original frame/crop references and do not increase paid call budgets without specific owner approval.

**Atlas and evidence interface.** A `ShelfAtlasRecord` contains a server-generated shelf-row ID, contributing saved frame IDs, validated transforms, covered extent, explicit gaps and a supported/unresolved status. Stitch or rectify **only overlapping views of approximately the same shelf plane**; split on shelf or wall changes and reject absent overlap, parallax, distorted book widths and implausible warp size. A stitched image is a spatial counting surface, not source text evidence or proof of room dimensions. An offline OpenCV check stitched an overlapping 59-book shelf pair, rejected an unrelated-shelf pair, and produced an implausibly huge result for one repeated five-book pair despite a success status; tests must reject that last case. Don't construct one whole-room panorama or require full 3D SfM.

**Spines and count.** Choose a dedicated *spine-instance* segmentation/detection adapter only after comparing it on the owner-labelled 14-book row and newly labelled representative views from the 59-book sweep; existing contour/boundary/VLM proposals are failed baselines. Candidate methods must be vetted for reproducible weights, licensing, privacy and available compute; generic SAM masks or model confidence alone are not a count. A `SpineInstanceRecord` ties an atlas polygon or oriented box to the original best frame/crop, confidence and unresolved reason. Deterministic code counts separated physical spine instances **once per validated shelf atlas**, including identical-title copies; book identity/OCR does not define existence or multiplicity. Validate overlap between atlas sections and shelf IDs before summing; unresolved masks, occlusion and coverage gaps keep `physical_book_count` null and appear in review. Do not price unresolved proposals as distinct property.

Use the sharpest **original-frame spine crops**, not blended panorama text, for OCR/VLM title, author, publisher, edition and ISBN with the existing conservative acceptance gate. The live voice agent guides capture and discusses only its current saved view; it does not author the post-sweep count. Keep non-book analysis, sourced prices, A4 same-plane measurement, room nullability, packet provenance and five-minute postwork as independently verifiable stages. The existing two five-book continuous sweeps, 59-book sweep and distinct/identical-copy controls test repeated views; the 14-book row tests single-image spine segmentation. These development fixtures cannot certify the ≤5% whole-room count bar. A compliant ≥60-book, independently labelled room and a new live iPhone run are still required; if atlas or detector evidence fails, report `NOT MEASURED` or `FAIL`, not a guessed number.

Research basis: [multi-image book segmentation/OCR with manually checked masks](https://arxiv.org/html/2407.19812), [overlapping-view/geometry requirements](https://colmap.readthedocs.io/en/latest/tutorial.html), and [browser-negotiated camera settings](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getSettings). They motivate the interfaces; their published datasets/results do not establish this app's accuracy.

### Optional Groq-first inference for the portfolio build

**Purpose and scope.** The owner wants as much Groq API use as defensible. In the first slice, one explicit server-side `INVENTORY_PROVIDER=openai|groq` setting selects Groq for saved-frame scene proposals, original-frame spine-crop reading **and candidate book-listing URL discovery**; `openai` remains the default. OpenAI WebRTC voice stays unchanged in this slice. Groq does not own sourced quote admission, catalogue/edition proof, metric measurement, packet arithmetic or physical counts. When Groq is selected, a missing `GROQ_API_KEY`, unavailable model or exhausted quota produces a saved failure/skip reason, never an automatic OpenAI fallback. Provider choice is fixed for an active sweep. Keys stay server-side, unlogged and out of Git. A Groq setting is not a guarantee of zero charges: account limits and tool billing need checking. No private-image upload, billed call or live Groq probe is authorized by this design; agree on inputs and budget separately.

**Interfaces and provenance.** Add narrow adapters at the existing frame-observation, crop-reading and listing-discovery seams, not a replacement agent framework. The image adapter translates Groq outputs into existing strictly validated `SceneProposal` and reading records; Python retains deterministic box mapping, crop/frame references, identity admission and review. The pricing adapter may propose **candidate URLs only**, never monetary facts. Persist actual provider/model/version, response ID, available raw response and usage, source references, stage time, and an estimated cost only when dated provider-specific rates and usage support it; unknown cost remains null, not zero. Do not impersonate an OpenAI response to reuse parsers. Separate provider/model/prompt/schema/evidence cache entries so earlier OpenAI output cannot become Groq evidence. Source text and model output remain untrusted; unobserved books, unsupported fields and physical counts stay unknown.

**Vision and reading quotas.** Start with Groq's documented preview vision model `qwen/qwen3.8-27b` and its supported strict JSON Schema mode; changing the model ID needs another reviewed contract. Each scene request contains one bounded saved-frame image. The Groq reading policy sends the **best original crop per book**, up to **three books/images per request**; save the existing rotated/original crop evidence locally without silently changing OpenAI's three-view reader. Unreadable vertical text stays unidentified. Retain existing per-sweep call, timeout and shared postwork ceilings, record selected/skipped denominators, and stop/defer on quota or deadline exhaustion without unbounded retries. Published free limits include 8K tokens/minute and 2,048 input tokens per image for this model, but exact organization limits require verification. Mock tests establish shape only, not accuracy, five-minute throughput or a zero-dollar bill.

**Listing discovery and real prices.** Groq's built-in `browser_search` is documented for Groq-hosted `openai/gpt-oss-20b`/`120b`, not the Qwen vision model; these are OpenAI-origin weights served by Groq, with no OpenAI API call when Groq is selected. Browser search cannot use strict structured outputs in the same request, so use a separate discovery adapter rather than reusing the current strict OpenAI discovery parser. Candidate HTTPS product URLs are eligible only if they appear in independently inspectable search-source URL evidence from the actual provider response. Model prose, a bracketed citation without its source URL, or a guessed URL is insufficient. The current browser-search documentation does not establish that this exact machine-readable URL evidence is returned: **do not promote or accept Groq discovery** until one separately approved, bounded public-book probe confirms that evidence and access/tool cost. If it does not, leave those slots null with a specific review reason; a future source-specific discovery adapter can be evaluated separately, but never fall back silently to OpenAI. Existing guarded fetching and source-specific quote admission must still check owned identity/equivalence, print format, new versus used condition, stock, source market, actual currency, retrieval date, FX and appraisal. A Groq-generated amount or used discount never enters totals.

**Voice is a separate next slice.** After the backend provider paths are locally verified, evaluate Groq-hosted transcription, text generation and speech synthesis as a separate voice design with a measured iPhone interruption and latency gate. Groq's separate speech endpoints are not a drop-in for the current full-duplex OpenAI WebRTC session; do not add LiveKit, EchoKit or a second transport in this first slice, remove voice capabilities, or claim Groq voice is implemented. Preserve capture and normal postwork when voice is unavailable.

**Tests and stop conditions.** Test-first with mocked HTTP only: default OpenAI behavior; Groq selection and missing key; one-image scene and three-image reading cap; strict scene/read response validation; bad/partial/refused/429 responses; matching original evidence refs; provider-isolated cache/usage/cost; no secret leak; and pricing rejection of uncited, unverifiable, wrong-market, out-of-stock or unsupported offers. Preserve existing Python/JavaScript gates without model calls. A separately approved Groq trial must measure source URL evidence on a public example before pricing promotion and compare selected labelled scene/crop results with the prior provider for localization, title accuracy, confidently wrong readings, latency, quota failures and cost. If those gates fail, report missing outputs rather than an invented success. Groq proposals do **not** substitute for the unvalidated physical-spine detector or promote `physical_book_count` from null. Sources: [Groq vision](https://console.groq.com/docs/vision), [structured outputs](https://console.groq.com/docs/structured-outputs), [browser search](https://console.groq.com/docs/tool-use/built-in-tools/browser-search), and [rate limits](https://console.groq.com/docs/rate-limits).

Non-book candidates get persistent IDs, category, visible description, dimensions when defensible, and frame reference. Include shelving, furniture, lamps, electronics, textiles, art, and decor when seen. Unreadable brand/model stays empty; generic products may use a sourced replacement range. Original/unknown artwork defaults to `needs_appraisal`; a user-established reproduction may be priced as a print, with that assertion recorded.

## Measurement and room geometry

A visible A4 sheet (21.0 × 29.7 cm) is the known-size metric reference. For spine calibration it must face the camera in approximately the **same vertical plane** as the spines, not lie flat on a horizontal shelf. Detect its corners in a usable frame, rectify that plane with a homography, and derive spine height/thickness and shelf run only for geometry to which that calibration applies. Store reference frame, plane, transform/scale method, pixel extents, and confidence. A marker on one shelf does not calibrate a different wall or depth; staggered spines, oblique views, occlusion, or missing references lower confidence or yield empty measurements and capture guidance. Do not assume the A4 sheet alone recovers three-dimensional room shape.

Attempt room length, width, ceiling height, floor area, wall area, and shelved wall area from visible calibrated planes and boundaries within the same sweep. For verified rectangular geometry, floor area is length × width, total wall area is 2 × (length + width) × height, and shelved wall area is the sum of measured shelf footprints (reported separately, not subtracted). For non-rectangular rooms use validated wall segments/polygon geometry, otherwise mark the shape unresolved. Convert m² to ft² deterministically. If required geometry is unobservable, return null for unsupported numeric fields and a review reason, not 0 or an LLM guess. The declared `scale_method` and confidence must describe the actual evidence. Browser-only room geometry is a **high-risk pass bar**; measure it against tape truth before claiming success. If the required errors cannot be met, record the failure and do not substitute an invented dimension.

## Pricing, packet, and failure behavior

For confidently identified ordinary books, retrieve replacement and used listings independently. Prefer UAE/AED for the primary locale; for ten of the same books also run a US/USD pricing test through the **same** locale-parameterized interface. Start with a small source feasibility test against public retailers/marketplaces; no price source or coverage is assumed until retrieval is demonstrated. Store amount or range, actual currency, source, retrievable URL, timestamp, condition (`good` for used comparison unless evidence says otherwise), exact/equivalent distinction, and evidence of any currency conversion with its dated FX source. Do not scrape behind authentication or invent a URL. If no defensible price or FX rate exists, set the amount to null, exclude it from totals, and route it to review. Non-books follow the same source discipline; generic equivalents use sourced ranges rather than fictitious SKUs.

`claim_packet.json` retains every mandatory field in build-spec section 29: sweep, room, books, items, totals, and review_queue, with optional provenance extensions. The illustrative zero values in that example are not evidence: unknown amounts/dimensions are null; unknown identification strings are empty as specified. Monetary values are decimal, in the packet locale after documented conversion, and summed in deterministic code. Excluded/uncertain/unpriced lines never silently contribute zero-valued *estimates* to totals: count them explicitly in `excluded_from_totals` and explain why. JSON validation checks frame links, identification status/fields, item pricing evidence/date/currency, appraisal suppression, totals, and reconciliation of book counts. Recoverable omissions become warnings and review entries; inconsistent sourced totals or broken evidence links block a final packet until corrected. `report.html` is rendered from the validated packet, with clickable local evidence links and visible source/date/uncertainty. If post-sweep work exceeds five minutes, show incomplete/failed status and persisted stage outputs rather than a fake complete packet.

Persist stage latency and provider usage/cost assumptions per sweep. Actual model/voice rates must be fetched at implementation time; do not print fabricated billing. Raw captures may include private material; ask users not to capture people or documents, keep runs local, avoid logging secrets, and keep runs/ground-truth captures out of version control unless deliberately reviewed.

## Test and evaluation contract

Start ground truth **before tuning**: hand-count and hand-read legible spines; tape-measure the room/shelves and at least 20 spine height/thickness pairs; manually verify at least 15 book prices against comparable source types; list non-books and categories. Keep the final dataset, predicted packet, and evidence paired with one compliant sweep. Unit tests cover totals, correction effects, deduplication, null/unknown fields, evidence paths, price source/FX validation, and appraisal exclusions. Integration tests cover live sweep state → packet/report, book → price → packet, and deterministic evaluator. Retain representative clear, blurry, glare, stacked, and unreadable frame fixtures. Check live behavior on the actual iPhone; mocks alone do not validate it.

The evaluator reports each pass bar without cherry-picking: book count error ≤5%; correctly identified human-legible titles ≥70%; confidently wrong identifications ≤3%; mean spine error ≤15% across 20 measured books; mean comparable book price error ≤25% across 15 books; non-book category recall ≥80%; floor area error ≤10%; wall area error ≤15%; final packet under five minutes. Define denominators and skipped/unknown cases explicitly; an unavailable metric is `NOT MEASURED`, never `PASS`. Record the three largest observed failures with evidence and root causes, and quantify at least one attempted improvement. Final submission additionally needs a private repository runnable from README in under 15 minutes, one unedited ≤6-minute demo, a matching packet/evidence, a one-page architecture note, and a one-page failure log. The assignment supplies a public reference-app link; source review is recorded, while its original live run remains blocked on unavailable Google credentials. The required read/run-before-code ordering was missed; do not report it fulfilled or make the obligation conditional on the source being supplied again.

## Delivery sequence and decisions

1. Preflight: device/secure-origin/Realtime concurrency, real public price source, sample room geometry feasibility, and reference-app availability. Record blockers; do not silently downgrade full-duplex voice or claim measurement compliance.
2. Working sweep: create session, persist frames, speak/listen, process a correction, show incremental inventory, produce valid partial packet/report.
3. Accuracy: quality guidance, spine candidates/tracking/evidence crops, conservative identification, A4 calibration, non-books, room geometry.
4. Pricing and claims: UAE/US retrieval, FX fallback, appraisal exclusions, validation, review, final packet and latency/cost recording.
5. Evaluation and handoff: ground truth, all pass bars, one measured fix, README, one-page architecture/failure notes, final real-room sweep and demo.

Complete and report preflight experiments for iPhone Safari concurrency, five-book UAE price retrieval, spine candidates on the current shelves, and A4-based measurement before fixing the final implementation choices. Finalize the entire remaining implementation plan from those results. Blockers affect only the relevant subsystem: failure of room geometry must not stop unrelated work, and unsupported measurements remain null with review reasons. No proposed fallback may invent claim values or quietly violate the single-sweep requirement.
